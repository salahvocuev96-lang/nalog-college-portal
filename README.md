# Education Portal · Налоговый колледж

Интерактивный прототип образовательной платформы колледжа: электронный журнал, дневник, расписание, посещаемость, домашние задания, сообщения, уведомления, администрирование и аудит.

Это **демонстрационная версия**. Расписание 22 групп взято из проекта расписания колледжа (репозиторий `2p1`, он не изменялся). Ещё 12 групп, студенты, родители и сотрудники администрации вымышлены.

## Быстрый старт

Нужен Node.js 22.13 или новее. Другие сервисы и базы данных не требуются.

```bash
npm install
```

```bash
npm run build
```

```bash
npm start
```

Откройте http://localhost:3000. При первом запуске сервер сам создаёт базу `data/portal.db` и заполняет её демо-данными.

Режим разработки: `npm run dev`. Тесты: `npm test`. Проверка типов: `npm run typecheck`.

> В эксплуатации сайт должен работать только по HTTPS: тогда cookie сессии автоматически получает флаг `Secure`. Подробности в docs/OPERATIONS.md.

## Тестовые аккаунты

На странице входа есть блок «Демонстрационный вход», который открывает кабинет одной кнопкой. Те же аккаунты работают и с паролем:

| Роль | Логин | Пароль | Кто это |
|---|---|---|---|
| Студент | `student` | `demo2026` | студентка группы 2П1 |
| Преподаватель | `teacher` | `demo2026` | Кудинова С.Л. (6 групп по расписанию) |
| Родитель | `parent` | `demo2026` | родитель студентки 2П1 |
| Учебная часть | `admin` | `demo2026` | роль COLLEGE_ADMIN |
| Технический администратор | `tech` | `demo2026` | роль TECHNICAL_ADMIN |
| Первый вход | `newstudent` | `temp-2026` | временный пароль, система потребует его сменить |

Остальным людям доступ выдаёт учебная часть в разделе «Аккаунты»: система генерирует временный пароль, который нужно сменить при первом входе.

## Что реализовано

**Вход и безопасность**
- Вход по логину и паролю (scrypt), сессия в httpOnly-cookie, в базе хранится только хеш токена.
- Обязательная смена временного пароля, проверка сложности пароля, блокировка подбора пароля (5 попыток, затем минута ожидания).
- Восстановление пароля: заявка попадает в учебную часть, которая выдаёт новый временный пароль.
- Все права проверяются на сервере. Браузер получает только данные, разрешённые роли: например, студент физически не получает чужие оценки. Запросы с чужих сайтов отклоняются.

**Студент и родитель**: главная (расписание на сегодня, последние оценки, средний балл, посещаемость, ближайшие задания, уведомления), электронный дневник по неделям с фильтром по предмету и переходом к дате, оценки за месяц, 1 и 2 семестр и год с расчётной итоговой оценкой и историей изменений, расписание, посещаемость, домашние задания со статусами, календарь месяца, сообщения, центр уведомлений, профиль.

**Преподаватель**: главная со списком необходимых действий (незаполненный журнал за сегодня, непрочитанные письма), электронный журнал (группа → предмет → дата), быстрый ввод и массовое заполнение с подтверждением, изменение оценки только с указанием причины, история изменений оценки, посещаемость отдельно от оценок, переход из расписания прямо в журнал занятия, домашние задания, свои группы и предметы, сообщения.

**Учебная часть**: обзор колледжа (студенты, преподаватели, группы, предметы, средний балл, посещаемость, последние изменения), управление группами и кураторами, студентами (поиск, фильтр, сортировка, карточка, импорт из CSV), преподавателями, родителями, предметами, назначениями преподавателей, редактирование расписания с проверкой занятости преподавателя и аудитории, аккаунты, объявления, учебные периоды и правило итоговой оценки, журнал аудита.

**Технический администратор**: состояние системы (проверка целостности базы, время работы, память, размер базы, применённые миграции), создание резервных копий, журнал событий без доступа к оценкам и персональным данным.

**Расписание** (перенесено из проекта `2p1`): настоящее время пар (09:00–10:30, 10:35–12:05 и т.д.), выбор группы с поиском, переключение дней недели, живой статус «идёт пара / перемена / до начала занятий» с обратным отсчётом, просмотр по дням и неделям.

## Что пока не реализовано

- Отправка уведомлений по email, push и в мессенджеры: архитектура это предусматривает (`NotificationChannel`), но работает только канал внутри портала.
- Отправка письма для восстановления пароля: сейчас заявку обрабатывает учебная часть вручную.
- Вложения к заданиям и сдача работ файлами: студент только отмечает статус.
- Экспорт ведомостей в Excel/PDF, электронный документооборот, интеграции с внешними системами, мобильное приложение.
- Восстановление из резервной копии через интерфейс: только вручную по инструкции.
- Двухфакторная аутентификация, вход через ЕСИА или Госуслуги.
- Несколько детей у одного родителя: модель данных это поддерживает, но интерфейс показывает первого ребёнка.
- Официальные правила итоговых оценок колледжа: в демо используется среднее арифметическое с выбором округления.
